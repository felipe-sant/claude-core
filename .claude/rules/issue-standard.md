# Padrão de issues

Vale ao criar issues do GitHub em qualquer repositório. Não trata de quadros de tarefas de outros sistemas.

## Título

- Uma frase em português simples que diz o problema ou o pedido, sem caminho de arquivo nem código.

## Corpo

Issue de bug, nesta ordem:

```
## O que aconteceu
## Impacto
## Causa provável
## Sugestão
```

Issue de funcionalidade, nesta ordem:

```
## O que se quer
## Por que
## Critérios de aceite
```

## Etiquetas e tamanho

- Use as etiquetas que o projeto já tem. Se houver `bug` e `enhancement`, use `bug` para bug e `enhancement` para funcionalidade. Não crie etiqueta nova.
- Nunca defina tamanho nem prioridade ao criar a issue: o tamanho é do dono do projeto (neste repositório, por exemplo, quem define é o agente de issues, que não existe nos outros).

## O que nunca vai na issue

O que nunca vai na issue está no `feedback-standard`: siga-o, porque issue em repositório público não leva dado sensível, de cliente nem caminho de arquivo.
